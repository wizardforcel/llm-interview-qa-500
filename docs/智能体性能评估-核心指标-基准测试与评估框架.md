## Q1. 为什么要评估智能体性能？不评估会怎样？

**回答**

在之前的章节，我们学了怎么构建智能体（ReAct、Plan-and-Solve、Reflection）、怎么用框架（AutoGen、LangGraph、AgentScope）、怎么搭低代码平台（Coze、Dify、n8n）、怎么做记忆与检索（RAG）、怎么做上下文工程、怎么做通信协议（MCP/A2A/ANP）、怎么做训练（SFT/GRPO）。这些都在解决“怎么让智能体跑起来”和“怎么让智能体更聪明”的问题。

但还有一个问题：**怎么知道智能体好不好？怎么知道它到底能不能干活？**

这就是**智能体性能评估**要解决的问题。

---

### 为什么要评估？

用大白话说，评估智能体性能，是为了回答下面几个问题：

| 问题 | 大白话解释 |
|------|-----------|
| 它能干活吗？ | 验证智能体是否具备完成特定任务的能力 |
| 干得怎么样？ | 量化智能体在不同维度上的表现（成功率、速度、成本……） |
| 和别人比怎么样？ | 在统一标准下，对比不同智能体系统的优劣 |
| 哪里有问题？ | 识别智能体的错误模式和改进方向 |

如果不做评估，你只能凭“感觉”判断智能体好不好，这在实际生产中很危险：

- 一个客服智能体“看起来能聊”，但实际退款率错了，可能导致经济损失；
- 一个编程智能体“看起来能写代码”，但代码跑不通，浪费开发者时间；
- 一个医疗助手智能体“看起来能给建议”，但给错了药方，可能有安全风险。

---

### 评估的核心目标（ASCII 图）

```
智能体评估的核心目标：

┌─────────────────────────────────────────────────────────────┐
│ 1. 能力验证：验证 Agent 是否具备完成特定任务的能力              │
│ 2. 性能量化：量化 Agent 在不同维度上的表现                      │
│ 3. 对比分析：在统一标准下对比不同 Agent 系统                    │
│ 4. 问题诊断：识别 Agent 的错误模式和改进方向                    │
└─────────────────────────────────────────────────────────────┘
```

---

### 不评估会怎样？（大白话比喻）

不评估智能体，就像雇一个员工但从不考核：

- 你不知道他干活快不快、准不准确；
- 你不知道他和别的员工比怎么样；
- 出了问题你也不知道是哪个环节出的问题；
- 最终可能是“看起来在干活，实际在捣乱”。

**面试要点**：评估智能体性能的核心目标是能力验证、性能量化、对比分析、问题诊断。不评估会导致“凭感觉用智能体”，在实际生产中可能带来错误决策、经济损失、安全风险。

## Q2. 智能体性能评估的核心维度有哪些？

**回答**

智能体性能评估不能只看一个指标（比如“成功率”），得从多个维度来看。下面咱们用大白话把核心评测维度逐个拆清楚。

---

### 核心评测维度对照表

| 维度 | 大白话解释 | 关键指标举例 |
|------|-----------|-------------|
| **任务完成** | Agent 能否成功完成给定任务 | 成功率、完成度 |
| **工具使用** | Agent 调用工具的准确性和效率 | 工具选择准确率、调用成功率 |
| **推理能力** | Agent 的逻辑推理和问题分解能力 | 推理步骤正确率、规划合理性 |
| **资源消耗** | 完成任务所需的资源和时间 | 步骤数、Token 消耗、响应时间 |
| **鲁棒性** | 面对异常情况的处理能力 | 错误恢复率、边界情况处理 |
| **安全性** | Agent 行为的安全合规性 | 越界操作率、敏感信息泄露率 |

---

### 逐个拆解

#### 1. 任务完成（Task Completion）

最基础的问题：智能体到底能不能把事情办成？

比如“帮我订一张从北京到上海的机票”，成功就是票订好了；失败就是订错了、订不成，或者半途而废。

**关键指标**：成功率（end-to-end task success rate）、完成度（任务完成了多少百分比）。

#### 2. 工具使用（Tool Use）

智能体的“手脚”是工具（搜索、计算器、API、数据库等）。评估工具使用，就是看它调用工具准不准确、效率高不高。

比如它该调搜索工具时却调了计算器，或者调用工具时参数错了，都算工具使用失误。

**关键指标**：工具选择准确率、工具调用成功率、多工具协同率。

#### 3. 推理能力（Reasoning）

智能体的“大脑”是推理。评估推理能力，就是看它逻辑不逻辑、能不能把复杂问题拆成小步骤。

比如“帮我调研竞品并写报告”，它能不能先拆成“搜竞品→查功能→对比定价→写报告”几个步骤，每一步逻辑都通顺。

**关键指标**：推理步骤正确率、规划合理性、上下文一致性（长对话里不矛盾）。

#### 4. 资源消耗（Resource Consumption）

干活要花钱（Token）、花时间。评估资源消耗，就是看它完成同一个任务，花了多少 Token、多少时间、多少步骤。

**关键指标**：步骤数、Token 消耗、响应时间、API 调用次数。

#### 5. 鲁棒性（Robustness）

现实环境是复杂的，网络可能抖动、工具可能报错、用户可能输入乱码。评估鲁棒性，就是看它遇到异常情况时，能不能优雅地处理，而不是直接崩溃。

**关键指标**：错误恢复率、边界情况处理率、重试成功率。

#### 6. 安全性（Safety）

智能体有调用工具的能力，如果用错了，可能造成危害。评估安全性，就是看它会不会越界操作、会不会泄露敏感信息。

比如它该不删除用户文件，结果误删了；或者它把用户的隐私信息发到了公开渠道。

**关键指标**：越界操作率、敏感信息泄露率、拒绝有害请求率。

## Q3. 核心指标怎么定义？

**回答**

维度确定了，接下来得把每个维度具体化成可测量的指标。下面咱们用大白话把常用核心指标一个个定义清楚。

---

### 核心指标定义表

| 指标 | 定义（大白话） | 计算公式（简化版） |
|------|--------------|------------------|
| **成功率** | 任务最终完成了的比例 | 成功任务数 / 总任务数 |
| **完成度** | 任务完成了多少（0~100%） | 已完成步骤 / 总步骤 |
| **工具选择准确率** | 选对了工具的比例 | 正确工具调用数 / 总工具调用数 |
| **工具调用成功率** | 工具调用没报错的比例 | 成功调用数 / 总调用数 |
| **推理步骤正确率** | 推理步骤全对的比例 | 正确步骤数 / 总步骤数 |
| **规划合理性** | 拆解的步骤是否合理 | 人评或 LLM 评分 |
| **步骤数** | 完成任务用了多少步 | 步骤总数 |
| **Token 消耗** | 用了多少 Token | 输入 Token + 输出 Token |
| **响应时间** | 从开始到结束用了多久 | 结束时间 - 开始时间 |
| **错误恢复率** | 出错后能自恢复的比例 | 自恢复次数 / 出错总次数 |
| **越界操作率** | 做了不该做的事的比例 | 越界操作数 / 总操作数 |
| **敏感信息泄露率** | 漏了敏感信息的比例 | 泄露次数 / 总交互次数 |

### 手撕核心指标计算 Python 代码

下面是一个最小可用的指标计算示例，展示怎么把原始评估结果转成指标。

```python
"""
metrics.py：智能体性能评估核心指标计算（简化版）
展示怎么把原始评估结果转成可测量的指标。
"""

from typing import List, Dict, Any


class EvaluationResult:
    """单次评估结果。"""

    def __init__(
        self,
        task_id: str,
        success: bool,
        completion: float,          # 0~1, 完成度
        tool_calls: int,            # 工具调用总数
        correct_tool_calls: int,    # 正确工具调用数
        successful_tool_calls: int, # 调用成功数
        reasoning_steps: int,       # 推理步骤总数
        correct_reasoning_steps: int, # 正确推理步骤数
        input_tokens: int,
        output_tokens: int,
        latency_seconds: float,
        error_recovered: bool,      # 出错后是否自恢复
        out_of_bounds: bool,        # 是否越界操作
        sensitive_info_leaked: bool, # 是否泄露敏感信息
    ):
        self.task_id = task_id
        self.success = success
        self.completion = completion
        self.tool_calls = tool_calls
        self.correct_tool_calls = correct_tool_calls
        self.successful_tool_calls = successful_tool_calls
        self.reasoning_steps = reasoning_steps
        self.correct_reasoning_steps = correct_reasoning_steps
        self.input_tokens = input_tokens
        self.output_tokens = output_tokens
        self.latency_seconds = latency_seconds
        self.error_recovered = error_recovered
        self.out_of_bounds = out_of_bounds
        self.sensitive_info_leaked = sensitive_info_leaked


class MetricsCalculator:
    """核心指标计算器。"""

    def __init__(self, results: List[EvaluationResult]):
        self.results = results

    def success_rate(self) -> float:
        """成功率：任务最终完成了的比例。"""
        if not self.results:
            return 0.0
        return sum(1 for r in self.results if r.success) / len(self.results)

    def avg_completion(self) -> float:
        """平均完成度。"""
        if not self.results:
            return 0.0
        return sum(r.completion for r in self.results) / len(self.results)

    def tool_selection_accuracy(self) -> float:
        """工具选择准确率：选对了工具的比例。"""
        total = sum(r.tool_calls for r in self.results)
        if total == 0:
            return 0.0
        return sum(r.correct_tool_calls for r in self.results) / total

    def tool_call_success_rate(self) -> float:
        """工具调用成功率：调用没报错的比例。"""
        total = sum(r.tool_calls for r in self.results)
        if total == 0:
            return 0.0
        return sum(r.successful_tool_calls for r in self.results) / total

    def reasoning_step_accuracy(self) -> float:
        """推理步骤正确率。"""
        total = sum(r.reasoning_steps for r in self.results)
        if total == 0:
            return 0.0
        return sum(r.correct_reasoning_steps for r in self.results) / total

    def avg_steps(self) -> float:
        """平均步骤数。"""
        if not self.results:
            return 0.0
        return sum(r.reasoning_steps for r in self.results) / len(self.results)

    def avg_tokens(self) -> int:
        """平均 Token 消耗（输入+输出）。"""
        if not self.results:
            return 0
        return int(sum(r.input_tokens + r.output_tokens for r in self.results) / len(self.results))

    def avg_latency(self) -> float:
        """平均响应时间（秒）。"""
        if not self.results:
            return 0.0
        return sum(r.latency_seconds for r in self.results) / len(self.results)

    def error_recovery_rate(self) -> float:
        """错误恢复率：出错后能自恢复的比例。"""
        errored = [r for r in self.results if not r.success]
        if not errored:
            return 0.0
        return sum(1 for r in errored if r.error_recovered) / len(errored)

    def out_of_bounds_rate(self) -> float:
        """越界操作率。"""
        if not self.results:
            return 0.0
        return sum(1 for r in self.results if r.out_of_bounds) / len(self.results)

    def sensitive_info_leak_rate(self) -> float:
        """敏感信息泄露率。"""
        if not self.results:
            return 0.0
        return sum(1 for r in self.results if r.sensitive_info_leaked) / len(self.results)

    def summary(self) -> Dict[str, Any]:
        """汇总所有指标。"""
        return {
            "success_rate": round(self.success_rate(), 4),
            "avg_completion": round(self.avg_completion(), 4),
            "tool_selection_accuracy": round(self.tool_selection_accuracy(), 4),
            "tool_call_success_rate": round(self.tool_call_success_rate(), 4),
            "reasoning_step_accuracy": round(self.reasoning_step_accuracy(), 4),
            "avg_steps": round(self.avg_steps(), 2),
            "avg_tokens": self.avg_tokens(),
            "avg_latency_seconds": round(self.avg_latency(), 3),
            "error_recovery_rate": round(self.error_recovery_rate(), 4),
            "out_of_bounds_rate": round(self.out_of_bounds_rate(), 4),
            "sensitive_info_leak_rate": round(self.sensitive_info_leak_rate(), 4),
        }


# ==================== 使用示例 ====================

if __name__ == "__main__":
    results = [
        EvaluationResult("task_1", True, 1.0, 3, 3, 3, 5, 5, 200, 300, 2.5, True, False, False),
        EvaluationResult("task_2", False, 0.6, 4, 2, 3, 6, 4, 300, 400, 4.2, False, True, False),
        EvaluationResult("task_3", True, 1.0, 2, 2, 2, 3, 3, 150, 250, 1.8, True, False, True),
    ]

    calc = MetricsCalculator(results)
    print("=== 智能体性能评估指标汇总 ===")
    for k, v in calc.summary().items():
        print(f"  {k}: {v}")
```

**运行输出示例：**

```
=== 智能体性能评估指标汇总 ===
  success_rate: 0.6667
  avg_completion: 0.8667
  tool_selection_accuracy: 0.7778
  tool_call_success_rate: 0.8889
  reasoning_step_accuracy: 0.8
  avg_steps: 4.67
  avg_tokens: 533
  avg_latency_seconds: 2.833
  error_recovery_rate: 0.5
  out_of_bounds_rate: 0.3333
  sensitive_info_leak_rate: 0.3333
```

### 这段代码的设计要点

1. **EvaluationResult**：单次评估结果，包含所有原始数据（成功与否、完成度、工具调用、推理步骤、Token、延迟、错误恢复、越界、泄露等）；
2. **MetricsCalculator**：把一批 EvaluationResult 汇总成各项指标；
3. **每个指标都有明确定义和计算公式**：成功率=成功数/总数，工具选择准确率=正确工具调用数/总工具调用数，等等；
4. **summary()**：一键输出所有指标，方便对比和报告。

**面试要点**：核心指标要可测量、可比较。常用指标包括成功率、完成度、工具选择准确率、工具调用成功率、推理步骤正确率、步骤数、Token 消耗、响应时间、错误恢复率、越界操作率、敏感信息泄露率。手撕代码时要体现每个指标的定义和计算公式。

## Q4. 基准测试是什么？常见的智能体基准有哪些？

**回答**

有了指标，接下来得有“标准答案”和“标准题目”来测。这就是**基准测试（Benchmark）**。

基准测试，大白话就是：**一套公开的、标准化的测试题和评分规则，用来比较不同智能体的优劣。** 没有基准，大家各说各话，这个说自己成功率 90%，那个说自己成功率 85%，但题目和评分标准都不一样，根本没法比。

下面咱们介绍几个常见的智能体基准测试。

---

### 常见智能体基准对照表

| 基准 | 发布机构 | 评测重点 | 任务类型 |
|------|---------|---------|---------|
| **AgentBench** | 清华大学等 | 综合 Agent 能力 | 8 种环境任务 |
| **GAIA** | Meta + HuggingFace | 通用 AI 助手 | 多步推理 + 工具使用 |
| **WebArena** | CMU | Web 交互能力 | 网页操作任务 |
| **OSWorld** | 多机构 | 操作系统交互 | 桌面操作任务 |
| **SWE-bench** | 多机构 | 代码修复能力 | 真实 GitHub Issue 修复 |
| **PaperBench** | 多机构 | 科研复现能力 | 复现顶会论文实验 |
| **BFCL** | 多机构 | 函数调用能力 | 工具调用准确性 |
| **Windows Agent Arena** | 多机构 | Windows 操作能力 | 多模态 OS Agent |

---

### 逐个拆解

#### 1. AgentBench（综合 Agent 能力）

由清华大学等机构发布，涵盖 8 种环境任务，适合综合评估 Agent 的各方面能力。

#### 2. GAIA（通用 AI 助手）

由 Meta 和 HuggingFace 发布，侧重多步推理 + 工具使用，适合评估通用 AI 助手。

#### 3. WebArena（Web 交互能力）

由 CMU 发布，侧重网页操作，适合评估能在浏览器里干活的 Agent（比如在网页上填表、点按钮）。

#### 4. OSWorld（操作系统交互）

由多机构发布，侧重桌面操作，适合评估能控制操作系统的 Agent（比如打开文件、运行软件）。

## Q5. 手撕 Python 代码：智能体评估器（成功率、工具调用准确率、Token 消耗、响应时间）

**回答**

有了指标定义和基准，接下来就要把评估落地成代码。下面咱们手撕一个最小可用的智能体评估器，能跑一批任务，计算成功率、工具调用准确率、Token 消耗、响应时间等核心指标，并输出报告。

> 注意：下面的代码是**概念版**，演示评估器的核心逻辑。真实项目中，要接入真实的智能体、真实的基准数据集、真实的工具调用。

---

### 完整代码：evaluator.py

```python
"""
evaluator.py：智能体评估器（最小可用版）
跑一批任务，计算成功率、工具调用准确率、Token 消耗、响应时间等核心指标。
"""

import time
from typing import List, Dict, Any, Callable
from metrics import EvaluationResult, MetricsCalculator  # 复用 Q3 的代码


class AgentEvaluator:
    """智能体评估器：跑任务、收结果、算指标。"""

    def __init__(self, agent_callable: Callable[[str], Dict[str, Any]]):
        """
        :param agent_callable: 智能体调用入口，输入任务描述，返回执行结果字典。
                               结果字典应包含：success, completion, tool_calls,
                               correct_tool_calls, successful_tool_calls,
                               reasoning_steps, correct_reasoning_steps,
                               input_tokens, output_tokens, error_recovered,
                               out_of_bounds, sensitive_info_leaked
        """
        self.agent = agent_callable
        self.results: List[EvaluationResult] = []

    def run_task(self, task_id: str, task_description: str) -> EvaluationResult:
        """跑单个任务，记录结果。"""
        start_time = time.time()

        # 调用智能体
        result = self.agent(task_description)

        end_time = time.time()
        latency = end_time - start_time

        eval_result = EvaluationResult(
            task_id=task_id,
            success=result.get("success", False),
            completion=result.get("completion", 0.0),
            tool_calls=result.get("tool_calls", 0),
            correct_tool_calls=result.get("correct_tool_calls", 0),
            successful_tool_calls=result.get("successful_tool_calls", 0),
            reasoning_steps=result.get("reasoning_steps", 0),
            correct_reasoning_steps=result.get("correct_reasoning_steps", 0),
            input_tokens=result.get("input_tokens", 0),
            output_tokens=result.get("output_tokens", 0),
            latency_seconds=latency,
            error_recovered=result.get("error_recovered", False),
            out_of_bounds=result.get("out_of_bounds", False),
            sensitive_info_leaked=result.get("sensitive_info_leaked", False),
        )
        self.results.append(eval_result)
        return eval_result

    def run_batch(self, tasks: List[Dict[str, str]]) -> None:
        """跑一批任务。tasks 格式：[{"task_id": "...", "description": "..."}, ...]"""
        for task in tasks:
            self.run_task(task["task_id"], task["description"])

    def report(self) -> Dict[str, Any]:
        """输出评估报告。"""
        calc = MetricsCalculator(self.results)
        return calc.summary()


# ==================== 演示版的“智能体”（模拟） ====================

def mock_agent(task_description: str) -> Dict[str, Any]:
    """
    演示版智能体：根据任务描述随机返回成功或失败，模拟真实智能体。
    真实项目中，这里应该调用真实的智能体。
    """
    import random
    random.seed(hash(task_description) % 1000)
    success = random.random() < 0.7
    return {
        "success": success,
        "completion": 1.0 if success else random.uniform(0.3, 0.8),
        "tool_calls": random.randint(1, 5),
        "correct_tool_calls": random.randint(0, 5),
        "successful_tool_calls": random.randint(0, 5),
        "reasoning_steps": random.randint(3, 10),
        "correct_reasoning_steps": random.randint(0, 10),
        "input_tokens": random.randint(100, 500),
        "output_tokens": random.randint(50, 300),
        "error_recovered": random.random() < 0.5,
        "out_of_bounds": random.random() < 0.2,
        "sensitive_info_leaked": random.random() < 0.1,
    }


# ==================== 使用示例 ====================

if __name__ == "__main__":
    evaluator = AgentEvaluator(mock_agent)

    tasks = [
        {"task_id": "t1", "description": "帮我查北京今天天气"},
        {"task_id": "t2", "description": "帮我计算 (23+47)*2 等于多少"},
        {"task_id": "t3", "description": "帮我写一个 Python 脚本爬取新闻标题"},
        {"task_id": "t4", "description": "帮我订一张下周五北京到上海的机票"},
        {"task_id": "t5", "description": "帮我总结这份会议记录的要点"},
    ]

    print("=== 正在跑评估任务 ===")
    evaluator.run_batch(tasks)

    print("\n=== 评估报告 ===")
    report = evaluator.report()
    for k, v in report.items():
        print(f"  {k}: {v}")
```

  error_recovery_rate: 0.4
  out_of_bounds_rate: 0.2
  sensitive_info_leak_rate: 0.0
```

### 这段代码的设计要点

1. **AgentEvaluator**：封装评估流程，`run_task()` 跑单个任务、`run_batch()` 跑一批任务、`report()` 输出报告；

## Q6. 评估框架怎么选？（工具链与公开排行榜）

**回答**

手撕评估器适合学习和小规模测试，但实际生产中，通常会用成熟的评估框架和工具链，省去自己造轮子的麻烦。下面咱们聊聊评估框架怎么选。

---

### 评估框架选型对照表

| 框架/工具 | 类型 | 适合场景 | 特点 |
|----------|------|---------|------|
| **LangSmith** | 评测工具链 | LangChain 生态，端到端追踪 | 可观测性强，与 LangChain 深度集成 |
| **Arize AI** | 评测工具链 | LLM 应用监控与评测 | 支持数据集管理、实验对比 |
| **公开排行榜**（HuggingFace Open LLM Leaderboard 等） | 排行榜 | 快速对比不同模型/智能体 | 公开、标准化，无需自建 |

### 逐个拆解

#### 1. LangSmith

#### 2. Arize AI

专门的 LLM 应用监控与评测平台，支持数据集管理、实验对比、模型漂移监测，适合生产环境的持续评估。

#### 3. 公开排行榜

比如 HuggingFace 的 Open LLM Leaderboard、各种 Agent 排行榜。适合快速了解不同模型/智能体的大致水平，无需自建评估环境，但可能不贴合你的具体业务场景。

#### 4. 自建评估器

如果你的业务场景很特殊（比如私有数据、特殊工具、特殊安全要求），公开基准和现成框架可能不够用，就需要自建评估器（就像 Q5 手撕的那样）。

## Q7. 评估上下文怎么选？（控制模拟 vs 开放世界，单轮 vs 多轮）

**回答**

评估智能体时，还得决定“在什么环境下评估”。这就是**评估上下文（Evaluation Context）**。不同的上下文，评估结果可能差很远。

---

### 评估上下文对照表

| 维度 | 选项 A | 选项 B | 适合场景 |
|------|--------|--------|---------|
| 环境 | 控制模拟（模拟环境） | 开放世界（真实浏览器/API/系统） | 控制模拟适合快速迭代，开放世界适合最终验证 |
| 轮次 | 单轮交互 | 多轮交互 | 单轮适合简单问答，多轮适合复杂任务 |
| 数据 | 公开数据集 | 私有业务数据 | 公开数据适合对比，私有数据适合业务验证 |

---

### 逐个拆解

#### 1. 控制模拟 vs 开放世界

- **控制模拟**：在模拟环境里跑，比如模拟一个网页、模拟一个数据库。优点是快、可重复、容易控制变量；缺点是可能不真实，现实环境里可能有意想不到的问题。
- **开放世界**：在真实浏览器、真实 API、真实操作系统里跑。优点是真实、能发现真实问题；缺点是慢、难控制、可能受外部因素影响。

**建议**：开发阶段用控制模拟快速迭代，上线前用开放世界做最终验证。

#### 2. 单轮 vs 多轮

- **单轮**：用户问一句话，智能体回答一次。适合简单问答。
- **多轮**：用户和智能体对话多轮，智能体需要保持上下文。适合复杂任务，比如“先帮我查航班，再帮我订票，最后把行程发邮件”。

**建议**：智能体通常涉及多步任务，多轮评估更能反映真实能力。

#### 3. 公开数据 vs 私有数据

- **公开数据**：公开基准的题目，优点是能和别人对比；缺点是可能不贴合你的业务。
- **私有业务数据**：你自己的业务场景，优点是贴合实际；缺点是没法和别人对比。

**建议**：公开数据做横向对比，私有数据做业务验证。

---

### 用 ASCII 图表示评估上下文选择

```
评估上下文选择：

环境：控制模拟（快、可重复） ──→ 开发阶段快速迭代
      开放世界（慢、真实） ──→ 上线前最终验证

轮次：单轮（简单问答） ──→ 基础问答场景
      多轮（复杂任务） ──→ 智能体核心场景

数据：公开数据集（可对比） ──→ 横向对比
      私有业务数据（贴合业务） ──→ 业务验证
```

**面试要点**：评估上下文包括环境（控制模拟/开放世界）、轮次（单轮/多轮）、数据（公开/私有）。开发阶段用控制模拟+单轮+公开数据快速迭代，上线前用开放世界+多轮+私有数据做最终验证。

## Q8. 评估结果怎么分析和诊断？

**回答**

跑完评估，拿到了一堆指标（成功率 80%、工具调用准确率 70%、Token 消耗高……）。但“指标低了”只告诉你“有问题”，没告诉你“问题在哪”。这就需要**结果分析和诊断**。

---

### 诊断思路（大白话）

| 指标低了 | 可能的原因 | 排查方向 |
|---------|-----------|---------|
| 成功率低 | 任务太难、推理错了、工具调错了 | 看失败案例，是推理问题还是工具问题 |
| 工具选择准确率低 | 模型不懂哪个工具干什么 | 看提示词里工具描述是否清楚，是否需要 few-shot 示例 |
| 工具调用成功率低 | 工具本身有问题、参数传错了 | 看工具返回的错误信息，是参数问题还是工具故障 |
| 推理步骤正确率低 | 模型逻辑不通、步骤拆错了 | 看推理链条，哪一步开始错了 |
| Token 消耗高 | 上下文太长、啰嗦 | 看上下文管理，是否需要压缩或截断 |
| 响应时间长 | 工具调用多、模型慢 | 看每步耗时，是工具慢还是模型慢 |
| 错误恢复率低 | 出错后不知道怎么办 | 看异常处理逻辑，是否有重试/降级 |
| 越界操作率高 | 权限控制不够、提示词边界不清 | 看安全约束层，是否有明确的越界检查 |

---

### 用 ASCII 图表示诊断流程

```
评估结果诊断流程：

拿到指标报告
     │
     ▼
哪个指标低了？
     │
     ├─ 成功率低 ──→ 看失败案例：推理错？工具错？
     │
     ├─ 工具准确率低 ──→ 看提示词：工具描述清楚吗？需要 few-shot 吗？
     │
     ├─ 工具成功率低 ──→ 看工具返回：参数错？工具故障？
     │
     ├─ 推理正确率低 ──→ 看推理链：哪一步开始错了？
     │
     ├─ Token 消耗高 ──→ 看上下文：需要压缩？需要截断工具输出？
     │
     ├─ 响应时间长 ──→ 看每步耗时：工具慢？模型慢？
     │
     └─ 安全性低 ──→ 看约束层：越界检查？敏感信息过滤？
```

---

### 诊断示例（ASCII）

```
诊断示例：

**面试要点**：评估结果诊断的核心是“找根因，不找表象”。成功率低不一定是模型差，可能是提示词不清、工具有问题、上下文太长等。需要结合具体指标，逐层排查。

## Q9. 评估的局限和注意事项

**回答**

评估很重要，但不是万能。下面咱们用大白话把评估容易踩的坑挑明。

---

### 局限 1：公开基准不等于业务场景

公开基准（GAIA、WebArena 等）的题目可能和你的实际业务不一样。在公开基准上得分高，不一定在你的业务里好用。

**应对**：公开基准做横向对比，私有业务数据做业务验证，两者结合。

---

### 局限 2：单一指标有偏差

只看成功率，可能忽略了安全性、成本、速度。比如一个智能体成功率 100%，但每次调用工具都花 10 秒、消耗大量 Token，实际用起来也不好。

**应对**：多维度指标一起看，不要只盯一个指标。

---

### 局限 3：评估数据本身可能有偏

公开基准的题目可能有固定模式，模型可能“背”了答案而不是真正掌握能力。

**应对**：定期更新评估数据，加入新的边界情况，避免过拟合公开基准。

---

### 局限 4：人工评估成本高

有些指标（比如规划合理性、回答质量）需要人评或 LLM 评，成本高、速度慢、主观性强。

**应对**：关键指标用自动化计算，主观指标用抽样人评或 LLM 评，建立人机协同的评估流程。

---

### 局限 5：环境差异导致结果不可复现

同一个智能体，在不同环境下（不同模型版本、不同工具版本、不同网络）表现可能不同。

**应对**：锁定环境版本，记录评估时的配置，保证结果可复现。

---

### 评估注意事项 Checklist（ASCII 版）

```
评估注意事项 Checklist：

┌─────────────────────────────────────────────────────────┐
│ □ 公开基准做横向对比，私有业务数据做业务验证              │
│ □ 多维度指标一起看，不要只盯成功率                        │
│ □ 定期更新评估数据，避免模型过拟合公开基准                │
│ □ 主观指标用抽样人评或 LLM 评，建立人机协同流程            │
│ □ 锁定环境版本，记录评估配置，保证结果可复现              │
│ □ 评估失败案例，做根因分析，而不只看总体指标              │
│ □ 安全性指标（越界操作、信息泄露）必须纳入评估            │
└─────────────────────────────────────────────────────────┘
```
